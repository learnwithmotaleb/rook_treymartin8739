## Reviewer walkthrough for version 1.0.1

Use the exact username and password in App Store Connect's protected App Review fields. On the normal **Sign In** screen:

1. In **Email**, enter `review:<reviewer email>` exactly as shown in the protected username field.
2. In **Password**, enter the current protected access code exactly as shown in the protected password field.
3. Tap **Sign In**. Do not use the reviewer email alone, an ordinary Clerk password, or a separate reviewer button.
4. If the app asks for current Terms acceptance or confirmation that the reviewer is at least 17, complete the in-app step before proceeding.

The actual access-code value is not available from workspace source and has not been confirmed in this audit. Confirm it in the protected production configuration and App Store Connect fields without placing it in source control or these docs.

From the four tabs, use **Alerts** → open a seeded example for the illustrative investigation flow. Workspace fixture evidence points both comparison sides to the same supplied review-sample image; in sample detail, their captions are **Your Photo** and **Example Image**. The hosted sample JPEG's SHA matches the supplied processed image. A read-only production query found six marked evidence rows with broken root-photo URLs before the current detail-response normalization source patch. Publish the web/API source and verify before promising corrected display. The sample account, findings, match details, and image are illustrative; they do not establish an actual impersonation or live discovery. Do not report or block an account based on this sample.

For version 1.0.1's photo flow, use the **Profile** tab, scroll to its **Settings** section, and choose **Photo Monitor**. Build 13 predates the current Photo Monitor changes. The seeded reviewer fixture does not include a verified connected account or monitored-photo list; the older build's list is local to the mobile app. Photo upload/import requires the relevant photo consent; only test with an authorized review image. The separate native **Review Example** is present in workspace source but not in build 13; it requires a newer signed build, which can still be version 1.0.1. Its exact managed build number is unknown; do not claim it is available in the currently attached build. The current web/API service is deployed at `https://tryrook.app`, and the hosted sample image is verified by SHA, but the detail-response normalization source change still requires publication; once published it normalizes only trusted marked samples and does not require sign-out/re-seed. For privacy controls, use **Profile** → scroll to **Settings** → **Privacy & Data**; policies are under **Legal & Privacy**, and subscription is under **Subscription** in that same section.
